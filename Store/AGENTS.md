# Project Rules

## Explanation

1. Explain technical terms in plain words
2. Before changing a file or running a command, explain the plan in three lines or fewer, and after the change, summarize what changed

## Specification

3. project_spec.md is the reference for this project. When the specification changes, update the code to match it, and never change only the code
4. Record every change in the change log at the end of project_spec.md with the date, what changed, why, and the result
5. Build only what is asked, in the simplest way

## Numbers

6. Mark every number you suggest as an assumption, and keep these numbers in one place at the top of the code file
7. Never make up unknown values : suggest an example and ask for confirmation

## Running

8. Save long outputs in the results folder and show only a summary
9. Run and check before saying a task is complete
10. Explain the cause of an error in plain words and fix it
11. Use the long procedures of skills (work procedures for the coding AI) only when the user asks

## File names

12. Write Python and data file names in lowercase English with underscores between words (e.g., config.py, customer_traits.csv)

## Security

13. Never upload raw store data, API keys or passwords to the web or a public repository
14. Cite the source of any external data
